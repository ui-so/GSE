맵은 X,Y 각각 -94.5~94.5m다. 각 마을 광장은 중심에서 (-10,+18)m이며 중심 마을 광장과 네 외곽 광장을 길로 연결한다. 연결 한 구간은 62m로 기본 걷기 3.1m/s에서 20초다. Shift 달리기, 전투, 대화, 우회 시간을 제외한 기준이다. 외곽끼리 중심 경유는 두 구간이다. 미니맵 숫자는 위 표의 마을 번호다.

## 실행 및 조작

`Tutorial/build.cmd`로 빌드한 `Tutorial/build/AshenShore.exe` 또는 배포된 `AshenShore.exe`를 실행한다. WASD 이동, Shift 달리기, E 대화/획득, Space 공격, Q 회복, P 풍경 기록, J 그림 수첩, F3 사건 단계, R 초기화/사망 회복, F1 기존 별도 사냥터. 첫 장이 완료되어도 다른 네 마을을 탐험할 수 있다.

`Monitor/start.cmd`는 로컬 JSON 수신기와 별도 Chrome 창을 연다. 실행 환경에 Python 3.10+와 Chrome이 필요하다. 웹 화면은 http://127.0.0.1:8765 이며 게임 없이도 열 수 있다. 별도 사냥터는 확장 지형과 구분되는 기존 F1 레벨이다.

## 주민과 소문

각 마을 20명 중 2명은 길잡이와 순회 상인이다. 다른 주민은 생업·휴식·상점·돌봄 행동을 한다. 중심 마을에는 마라·오렌·세라·엘린·리오·하온의 첫 장 역할을 보존했다. 나머지 네 마을은 후속 장을 완성한 지역이 아닌 탐험·교역·소문 테스트 지역이다.

- 중심의 처음 소식은 숲길 짐승 증가다. 경고·대피·정지 사건은 중심에만 새 소문을 만든다.
- 순회자는 A*로 길을 걷고 목적지 광장 1.8m 안에 도착해야 마을 소식판과 지식을 교환한다. 중심은 외곽을 순환하고 외곽은 중심과 고향을 왕복한다. 4초간 광장에서 쉬고 다시 출발한다.
- 현지 주민은 해당 마을 소식판을 통해 이미 도착한 소식을 공유한다. NPC 간 말하기 애니메이션·인물별 접촉망은 아직 모델링하지 않는다.
- 플레이어의 이동·화면 컬링·사건 타이머만으로 원격 마을의 지식이 생기지 않는다. 모든 마을 시뮬레이션은 확장 월드가 활성화되면 계속 진행한다. F1 사냥터·수첩·휴식·비활성 창에서는 정지한다.
- 도착 기록에는 carrier Actor, 소문 번호, 게임 시간, 실제 좌표가 포함된다. 소문 번호 0 짐승, 1 탈색 징후, 2 대피, 3 국소 정지. 순회자가 정지하면 다음 마을에 도착할 때까지 전파되지 않는다.

## 몬스터와 재생성

마을 안전 구역 밖, 연결 길에서 10m 이내의 충돌 없는 후보지에 몬스터 슬롯 100개를 배치한다. 마을 안을 추격하지 않으며 주민을 공격하지 않는다. 처치하면 경험치 20과 한 번만 얻을 수 있는 동전·물약 드롭을 준다.

3초 후 처치 지점과 12m, 플레이어와 14m, 살아 있는 다른 몬스터와 1.6m 이상 떨어진 다른 후보를 찾는다. 같은 Actor를 재활성화한다. 프레임당 최대 4개라 동시 대량 처치 때는 순차 처리되며 후보가 없으면 0.25초 뒤 재시도한다. 드롭 Actor는 최대 128개로 재사용하고 미획득 드롭은 게임 시간 60초 뒤 정리한다. 저장 파일에 몬스터·소문 진행을 유지하는 기능은 없다.

## 분위기 통계

각 마을의 평온·불안·신뢰·희망은 0~100의 프로토타입 수치이며 합계 100인 비율이 아니다. 0.5초마다 실제 상태에서 다시 계산한다. 인덱스 i는 위 표 번호-1이다.

- 불안 = 10 + 2i + 현지 사건 단계×14 + 알려진 소문 가중치(4/5/7/10) + min(반경34m 생존 위협,16)×0.5 + 정지 주민×3.
- 평온 = 100 - 불안.
- 신뢰 = 65 + 2i + 기록한 주민 수 + min(새 소문 도착 수,8)×1.5.
- 희망 = 72 - 2i - 현지 사건 단계×7 - 정지 주민×4 + 기록 주민×0.7 + 빵 나눔×3.
- 모든 수치는 0~100으로 제한한다. 정지 주민이 있으면 애도, 아니면 불안 50 이상은 불안, 25 이상은 경계, 나머지는 평온이다. 현지 사건 단계는 중심 마을에만 적용한다.

마을 카드에 소속 인구20, 현지 인원(방문자 포함), 이동/대기/대화/정지, 소문 수와 최근 전달자가 표시된다. NPC 표에는 소속·현재 위치·목적지·순회자 여부·소지 소문 수를 표시한다. 소속 인구를 기준으로 표를 묶으므로 순회자가 마을을 떠나도 20명은 유지된다.

JSON v1의 `worlds`는 관측 구역이다. 마을5 + 숲길1 + 기존 사냥터1, 총7개를 보고한다. 마을 몬스터는0, 숲길 몬스터는100이며 중복 합산하지 않는다. 기존 사냥터 몬스터는 별도 레벨 수치다.

## 검증과 프로파일링

- `--self-test`: 주민100명 접근, 네 연결 도로의 실제 WASD 20초 이동, 원격 소문 지연과 도착 위치, 마을별 분위기 범위, 리젠 위치 변경 및 Actor/드롭 재사용, 첫 장 전체 진행, 기존 사냥터 회귀 검사.
- `--capture-region --quiet-profile --validate-render`: 다섯 마을, 숲길, 소문 순회 화면. `--capture-story`는 기존 첫 장과 수첩 회귀 캡처.
- `--benchmark --tutorial --quiet-profile --validate-render`: 초기 중심 마을 140프레임. `--benchmark-region`은 순회 시뮬레이션 후 숲길 시나리오. 20프레임 워밍업 뒤120프레임을 분석한다.
- `python Monitor/test_monitor.py`: JSON/HTTP 검사. `--integration Tutorial/build/AshenShore.exe <출력폴더>`는 실제 C++ 전송기 10개 메시지로 인구·원격 소문·분위기·F1 전환을 검증한다. 8765 포트는 비어 있어야 한다.

프로파일은 `Tutorial/PROFILING.md`를 따른다. 확대 자체가 프레임 성능 목표 달성을 의미하지 않는다. 실제 측정 결과와 제한은 검증 보고서에 별도 기록한다.
