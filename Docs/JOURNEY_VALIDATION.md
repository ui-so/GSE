- 실제 GPU 캡처: 잠긴 페이지, 호수/꽃길/정지 숲, 제빵사 대사, 대피, 완료, 1000×720 수첩 확인. 후처리 뒤의 수첩 이미지가 올바른 방향·비율로 표시되며 텍스트 겹침 없음.

- 세 이미지 로딩 이벤트를 확인했다. 캡처는 세 이미지와 작은 창의 마지막 그림을 포함하여 이미지 제출 4회를 기록한다. 한 프레임의 여러 draw이므로 정상 프레임 비용으로 비교하지 않는다.

## 동선과 시간

실제 충돌 격자의 고정 시작 배치를 따라 마라·호수·리오·묘목·제빵사·가족·성직자·집결지·묘목·마라·출구를 이은 최단 경로 합은 약 171m다. 걷기 3.1m/s와 대화·감상·탐험 여유 180초를 더한 설계 예상은 235.16초다. 집결지 필수 대기는 약 5초이므로 이를 별도로 더해도 5분 이내다. 실제 NPC 이동과 읽기·탐험 시간에 따라 달라지며 수동 최초 플레이 완료를 측정한 수치는 아니다. 수첩 중 게임 타이머는 정지하지만 현실 시간은 흐른다.

## 평상시 성능 표본

Intel Iris Plus / OpenGL 4.6, 1280×800, 시드 42, 워밍업 20프레임 후 120프레임. quiet 로그·GL 오류 검사, 벤치마크 전용 GPU 완료 대기 포함.

- 마을 평균 30.95ms, P95 41.02ms, 평균 draw call 144.56.
- 기존 60 FPS 예산은 여전히 초과했다. 이미지 추가로 성능 목표를 달성했다는 의미가 아니다. 시스템 부하가 다른 이전 결과와 직접 비교해 회귀·개선을 단정하지 않는다.
- 이미지 디코딩/업로드는 시작 시 한 번 수행한다. 런타임 생성 서비스·외부 PNG 탐색·프레임별 파일 읽기는 없다. 텍스처 데이터 약 18MiB를 유지한다.
- `journey_*`, `journal_art_*`, `journal_ui_cpu`, GPU `journal_ui` 계측으로 목표 갱신·이미지 로딩·수첩 표시를 별도 관찰한다.

실행 파일·캡처·원시 JSONL·벤치마크 요약은 작업 공간 `outputs/JourneyChapter`에 저장했다. 이미지 원본과 생성 프롬프트는 `Tutorial/Assets/Journal`에 보존했다. 진행 상태는 이번 실행 동안 유지하며 다음 지역·저장 기능은 포함하지 않는다.
