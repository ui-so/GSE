# 첫 장: 남겨진 색과 사람들

기준 서사는 사용자 제공 [스토리 시안](story_draft_v1.md)이다. 이 장은 현재 마을에서 평범한 여행자가 풍경과 사람들의 이야기를 기록하기 시작하는 프로토타입이다. 인물명·세부 대사·이미지의 반려동물 디자인은 임시 설정이다.

## 실행과 조작

Windows x64 `AshenShore.exe` 실행 후 마라에게 E로 말을 건다. 금빛 목적지 표시와 왼쪽 상단 목표를 따라간다.

- WASD 이동, Shift 달리기, E 대화/대화 닫기/전리품 획득.
- P: 호숫가 또는 북쪽 묘목 근처에서 현재 목표의 풍경 기록. 해당 그림이 수첩에 열린다.
- J: 어디에서든 수첩 열기. 좌우 방향키 또는 1~3으로 페이지 선택. J/P/E/Esc로 닫기.
- 수첩 중 NPC·몬스터·이벤트 타이머·플레이 시간 정지. 잠긴 그림은 기록 장소를 방문한 뒤 열린다.
- Q 회복약, Space 공격, 상인 대화 중 1 구매, 성직자 대화 중 2 치료. 이야기 완료에 전투는 필요하지 않다.
- F3 사건 앞당기기(개발용), F2 후처리, F1 기존 사냥터. Esc 휴식, 휴식 중 Q 종료, R 재시작.

## 목표 순서

| 단계 | 목표 | 진행 조건 |
|---|---|---|
| 0 | 마라와 여행 이야기 | E 대화 |
| 1 | 함께 보았을 호수 | 호숫가 `(10,-5)` 주변에서 P, 그림 1 해금 |
| 2 | 아이 리오 | 리오(20번 인덱스)와 대화 |
| 3 | 파란 꽃이 있는 길 | 북쪽 묘목 `(0,-13)` 주변에서 P, 그림 2 해금 |
| 4 | 마지막 빵 | 징후 자동 시작 후 오렌/미나와 대화 |
| 5 | 서로 찾는 가족 | 엘린과 리오 각각 대화. 같은 인물 반복으로 완료되지 않음 |
| 6 | 살아 있는 이의 돌봄 | 세라/수도자/수습 사제와 대화 |
| 7 | 대피 목격 | 대피 자동 시작, 남쪽 `(0,18)` 반경 4에 누적 5초 머물기 |
| 8 | 멈춘 숲의 기록 | 국소 정지 자동 진행, 북쪽 묘목 주변에서 P, 그림 3 해금 |
| 9 | 마라에게 기록 전달 | 마라와 대화 |
| 10 | 여행을 계속할 준비 | 남쪽 출구 `(0,26)` 반경 2에 도착 |
| 11 | 첫 장 완료 | 세 그림을 J로 다시 감상 |

NPC는 계속 이동하므로 목적지 표시는 해당 Actor를 따라간다. 사건 타이머가 먼저 지나거나 F3을 일찍 눌러도 필수 주민의 대화로 진행할 수 있다. 기록은 탈색을 해제하지 않으며 정지한 인물과 숲은 남는다.

현재 첫 장의 종료 지점까지 구현했다. 다음 지역 이동·자유 그림 편집·진행 저장은 아직 제공하지 않는다. R/F1 전환 후 마을 재시작 또는 앱 재실행 시 첫 장도 초기화된다. 기본 경로와 대화/감상 180초 여유를 합쳐 5분 이내를 목표로 검사하며 실제 읽기·탐험 시간은 개인차가 있다.

## 사전 생성 이미지

| 파일 | 그림 | 용도 |
|---|---|---|
| `Tutorial/Assets/Journal/lakeside-v1.png` | 호수와 마을의 일상 | 첫 풍경, 개인적 애도 |
| `Tutorial/Assets/Journal/blue-flowers-v1.png` | 아이·어머니와 파란 꽃 | 사람의 말이 풍경 곁에 더해지는 장면 |
| `Tutorial/Assets/Journal/stillness-v1.png` | 정지한 묘목지기와 숲 | 잃은 삶을 되돌리지 않는 기록 |

세 이미지는 **기본 내장 image_gen 도구**로 사전 제작했다. 정확한 최종 프롬프트는 [generation.json](../Tutorial/Assets/Journal/generation.json)의 세 `prompt` 필드에 보존했다. 공통 프롬프트는 중세 마을의 수채화·연필 여행 기록, 어둡고 쓸쓸하지만 온기 있는 분위기, 그림마다 기억으로 그려 넣은 작은 여우형 반려동물, 글자·UI·워터마크 없음이다. 개별 장면은 호숫가의 생업, 파란 꽃과 가족, 국소 탈색·정지와 떠나는 사람들이다.

PNG는 `JournalAssets.rc`의 RCDATA로 실행 파일에 포함한다. Windows WIC가 시작할 때 한 번만 RGBA로 디코딩하고 OpenGL 텍스처로 올린다. 별도 PNG 복사, 현재 작업 경로, API 키, 인터넷 연결이 필요하지 않다. 외부 파일이 없어도 테스트/실행 가능하다. 원본 PNG는 향후 교체·검수를 위해 저장소에 보존한다.

`Journey.h/.cpp`는 퀘스트 상태 기계, `JournalArt.h/.cpp`는 내장 이미지 로딩·제출, `Tutorial.cpp`는 Actor 기반 목적지·대화·수첩 UI를 연결한다. 그림 수첩도 `TravelJournal` 인터페이스 Actor로 제어한다. 이미지 누락/실패는 로그와 한글 안내로 표시한다.

## 검사

`Tutorial/build.cmd` 또는 Tutorial.sln으로 빌드한다. RC와 Windows WIC는 Windows SDK를 사용한다.

- `--self-test`: 필수 인물 순서, 중복 대화 제한, 기록 해금, 사건 선행 복구, 집결지 대기, 첫 장 완료·재시작, 수첩 시간 정지, 내장 PNG 3장 디코딩 및 기존 게임 회귀 검사.
- `--capture-story --quiet-profile --validate-render`: 실제 상호작용을 순서대로 실행해 세 이미지와 UI를 GPU 캡처.
- `--benchmark --tutorial --quiet-profile --validate-render`: 평상시 마을 성능. 수첩 열림 비용은 별도 `journal_ui_cpu`/`journal_ui`로 관찰한다.
