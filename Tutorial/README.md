# 잿빛 여울 — 튜토리얼 v0.2

기존 Tutorial.sln / Tutorial.vcxproj를 업데이트했다. 레벨명과 인물명은 프로토타입용 임시 설정이다. 한국어 UI·대사와 생명·죽음·미지의 존재라는 기본 주제를 유지한다.

## 실행과 조작

Windows x64용 AshenShore.exe를 실행한다. 외부 에셋이나 DLL 복사 없이 실행되며 맑은 고딕으로 한글을 표시한다.

- WASD: 화면 기준 이동. 대각선 속도 정규화.
- Shift: 빠르게 걷기.
- E: 주민과 대화, 씨앗·추모석 조사, 대화 진행.
- Esc: 일시정지 / 계속.
- R: 일시정지 또는 완료 화면에서 처음부터 다시 시작.
- Q: 일시정지 화면에서 종료.
- F2: 장면 후처리 켜기 / 끄기 비교. UI에는 후처리를 적용하지 않는다.

## 이번 업데이트

### 렌더링

- 장면을 화면 크기의 텍스처로 복사한 뒤 GLSL 후처리 패스에서 밝은 영역 블룸, 색조·감마 조절, 약한 가장자리 명암과 미세 노이즈를 적용한다. 마지막에 한국어 UI를 그린다.
- 그림자는 바닥에 투영한 단순화된 실루엣과 여러 겹의 가장자리, 연속 알파 텍스처의 접지 그림자로 표현한다. 실제 광원별 3D 섀도맵은 아니다.
- 석재 포장, 흙길, 풀, 수면용 절차적 텍스처를 생성한다. 목조 골조, 문 판자와 손잡이, 지붕재·굴뚝 줄눈을 추가했다.
- 캐릭터는 후드, 얼굴, 어깨, 튜닉, 벨트, 장갑, 바지, 장화와 등불을 구분했다. 런타임에 RGBA 스프라이트 시트를 생성해 실제 UV 프레임을 선택한다. 팔레트 4종 × 방향 4종 × 대기·걷기·상호작용 3종 × 8프레임이다.
- 호수는 흐르는 수면 텍스처, 파문, 해안 돌과 흔들리는 갈대를 포함한다. 모닥불에는 움직이는 불꽃, 불티, 빛 번짐을 적용했다.
- 나무 형상은 OpenGL 디스플레이 리스트로 재사용하고 화면 밖 지형과 오브젝트의 그리기를 제외한다.

### 월드와 주민

플레이 가능 영역을 기존 41×37에서 82×74 월드 단위로 늘렸다. 면적은 1,517에서 6,068로 정확히 4배다. 숲과 외곽 길, 작은 야영지를 확장했다. 마을 주민은 8명에서 16명으로 늘렸고 각자 다른 한국어 대사를 가진다. 추가된 주민은 대장장이, 묘지기, 목수, 재봉사, 양봉가, 수습 사제, 어부와 숲지기다.

### 야생동물

사슴 5마리, 산토끼 5마리, 멧돼지 5마리를 배치했다. 주변을 배회하며 서식지에서 너무 멀어지면 돌아오고, 플레이어가 3.6 월드 단위 이내로 접근하면 달아난다. 나무, 건물, 호수와 월드 경계를 통과하지 않는다. 다리·귀·뿔·엄니로 종을 구별하며 이동 애니메이션을 가진다. 이번 버전의 동물은 비전투 관찰 대상으로 공격이나 피해 시스템은 없다.

## 퀘스트와 플레이 시간

마라와 대화 → 북쪽 숲의 숨빛 씨앗 → 동쪽 호숫가 추모석에 심기 → 마라에게 귀환.

필수 동선은 약 45m로 유지했다. 기본 속도의 이동 시간과 180초의 대화·탐색 여유를 합친 설계상 예상은 약 195초다. 필수 튜토리얼은 3–5분을 목표로 하며 확장된 외곽은 선택 탐색용이다. 실제 최초 플레이 시간은 읽기 속도와 탐색에 따라 달라진다. 시간 제한은 없고 완료 후에도 탐색 가능하다.

## 코드와 빌드

- Tutorial.cpp: 월드·주민·야생동물, 입력, 퀘스트, 장면 그리기와 한국어 UI.
- Visuals.h / Visuals.cpp: 재질 텍스처, 스프라이트 시트, 부드러운 그림자 텍스처, 후처리 셰이더와 GPU 자원 정리.
- Tutorial.vcxproj 및 build.cmd에 Visuals.cpp를 포함했다. 기존 SimpleGame 샘플은 보존했다.

Tutorial/build.cmd를 실행하면 Tutorial/build/AshenShore.exe를 생성한다. Visual Studio 2022 C++ x64 도구와 Windows SDK가 필요하다. Tutorial.sln도 기존 경로에서 열 수 있다. 이 환경에서는 MSBuild의 사용자 SDK 디렉터리 접근 제한이 있어 검증된 build.cmd로 빌드했다.

후처리는 OpenGL 셰이더 기능이 필요하며 초기화 실패 시 기본 장면 렌더링을 유지한다. 현재 Intel Iris Plus의 OpenGL 4.6에서 후처리 활성화를 확인했다. 렌더러는 프로토타입용 OpenGL 호환 모드다.

## 검증

- MSVC x64 /W4 /WX 빌드: 경고 없이 성공.
- --self-test: 기존 퀘스트 순서·이동·일시정지·재시작에 더해 16명 상호작용 및 접근 가능성, 정확한 4배 면적, 동물 수·이동·충돌·도주를 검사한다.
- --capture: 실제 GPU로 마을·호수·야생동물·대화·작은 창과 후처리 비교, 걷기 프레임, 스프라이트 시트를 저장한다. 검수용 고정 상태이므로 직접 플레이 완료를 의미하지 않는다.
- --benchmark: 20프레임 준비 후 1280×800에서 120프레임의 장면+후처리+UI 그리기 및 GPU 완료 시간을 측정한다. 프레임 대기와 창 표시 비용을 제외하므로 사용자 체감 FPS와 동일하지 않다.

전투, 저장, 인벤토리 UI, 음향과 청크 스트리밍은 이번 변경 범위에 포함하지 않는다.

최종 성능 참고: 이 장치의 Intel Iris Plus에서 1280×800, 준비 20프레임 후 120프레임의 평균 그리기·GPU 완료 시간은 약 25.5ms였다. 측정 당시 시스템 상태의 영향을 받으며 실제 표시 FPS 보장은 아니다. 후처리는 분기·반복문 대신 명시적인 4방향 밝기 샘플을 사용하고, 정적 지형과 나무 형상은 재사용한다. F2로 후처리 비용과 화면 차이를 비교할 수 있다.
